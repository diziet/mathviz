# MathViz

MathViz generates 3D mathematical forms, such as strange attractors, fractals, knots and
minimal surfaces, and prepares them for subsurface laser engraving in crystal glass blocks.

## Tasks

Most tasks in `tasks.md` have a **Suggested path:** section. It is one way to reach the
**Objective:**, not a specification to implement literally. Deviate from it when you have a good
reason. The **Objective:** defines success.

The tests listed under **Tests:** are the minimum. Add tests for edge cases you find during
implementation.

## Workflow

- Do each task in its own worktree: `make worktree b=<type>/<short-name>`, where `<type>` is one
  of `feat`, `fix`, `docs`, `refactor`, `perf`, `test`, `chore`. It creates
  `~/projects/mathviz/<type>/<short-name>` from `origin/main`, creates the tree's own `.venv` with
  the package, its `dev` and `render` extras and the pinned ruff, and installs the hooks. Commit,
  push and open the PR from that worktree.
- Do not edit, stage, commit or check out files in the primary checkout
  `~/projects/mathviz/mathviz/`. Local `main` is a read-only mirror of `origin/main`: the hooks in
  `.githooks/` refuse a commit or merge commit on `main`, a push to `main`, and a move of `main`
  to a commit that `origin/main` does not contain. `make sync` fetches and fast-forwards the
  current branch.
- Never run `git stash`. Every worktree of the repo shares one stash stack.
- While you work, run the smallest relevant test. `make gate` runs `doc-facts-check`,
  `doc-refs-check`, `gate-wiring-check`, `lint` (`ruff check .`) and `test` (`pytest`). Every PR
  runs all five stages. There is no docs-only mode, because `tests/test_docs` reads `README.md`
  and `docs/*.md`, so a Markdown-only change can fail `test`.
- `make merge pr=N` is the only merge path. It runs the gate on the preview merge of the PR into
  `origin/main` and merges with a merge commit only if neither parent moved. Run from the PR's
  worktree, it then removes that worktree and its branch; `keep=1` keeps them. Never run
  `gh pr merge`.
- Autopilot merges its own task PRs through `lib/merger.sh`; every other PR follows the rules
  above.
- Tool pins are `PYTHON_VERSION` and `RUFF_VERSION` at the top of the `Makefile`. The Python
  packages in `pyproject.toml` have lower bounds only. `make doctor` checks the pins, the venv,
  `docs/generators.md` and the hooks in seconds; run it first when a gate fails for no visible
  reason. `make help` lists every target.
- `make branches-gc` only reports. `make branches-gc args=--delete` deletes merged branches only.
- A value between `<!-- fact:NAME -->` and `<!-- /fact -->` is generated by
  `scripts/doc_facts_registry.py`. Change its source, then run `make doc-facts`.
  `make doc-refs-check` fails when a code span names a path, `make` target or flag that does not
  exist. Exempt a correct reference only in `docs/doc-refs-allow.txt`, with a reason.
  `tests/tooling/test_doc_checks_repo.py`, which `make test` runs, fails when an edit removes a
  reference it requires.
- Prose follows `docs/writing-style.md`.
